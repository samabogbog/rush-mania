# Imported monster and level balance

Source files are preserved unchanged in `docs/balance/imported/monsters.csv` and `levels.xlsx`. The effective editable runtime values live in `src/config/content.json` (`normalBalance`) and `src/config/progression.json` (`levels`). Both browser practice and authoritative server use these values. The workbook multiplier column is retained as source data; `nextLevelXp` is authoritative and is not recalculated from the multiplier.

All 100 workbook rows retain their original numeric values, including the source Lv100 requirement. The game remains capped at Lv100: its runtime next requirement is zero and further EXP never grants Lv101. EXP rewards keep the existing rounding and charm/gear multipliers; thresholds retain spreadsheet precision. The display rounds earned EXP and rounds the next threshold upward for readable integer presentation. Character HP/MP/ATK/DEF growth, stat points, skills, equipment, and recipes are unchanged.

The CSV has no species IDs. Its nine Normal rows map by monster level, not row order or name. HP/ATK/DEF/gold and each drop probability interpolate linearly between checkpoints 10–90. Below Lv10 the stats/gold scale by level/10 and drop probabilities use Lv10; above Lv90 everything clamps to Lv90. The missing comma in Lv40's drop text is parsed as a separator between two named rates. Blank CSV rows are ignored.

Existing elite factors are explicit editable knobs: bosses HP×16, ATK/DEF×3, gold/EXP×12; minibosses HP×5, ATK/DEF×1.8, gold/EXP×4. Base EXP for every tier comes from the workbook at that monster's exact level. Existing persisted administrator overrides still take precedence over these defaults. The numeric hp/atk/defense/xp/gold fields in `content.species` are the previous release's snapshot for the one-time HP migration; edit `normalBalance` and `progression.levels` for active balance. Species identity, appearance, level, AI timings and original unrelated drop names remain active there. Operator catalogs and HP displays use effective runtime values.

Normal monsters and minibosses independently roll one Common refine stone and six material entries (Shade essence, Rune stone, Sky feather × Common/Rare). A successful entry grants one item; multiple different entries can succeed on the same kill. Probabilities are fractions, and exactly zero never drops even when the random sample is zero. The old guaranteed drop is suppressed when it is one of those three crafting materials, so it cannot bypass the table. Original unrelated materials remain. Bosses retain the previous refine/material tables, three-item crafting material counts and guaranteed species material. Existing equipment drop probabilities remain 16% for Normal/Mini and 75% for Boss, with their previous rarity tables. Rare refine stones remain available from bosses and the existing 5 Common → 1 Rare recipe.

Existing player level, EXP progress, allocated stats/points, gold, inventory, equipped items, account data and party data are preserved. Loading alone grants no levels: if saved EXP now exceeds the new requirement, progression is evaluated on the next legitimate EXP award. Existing cap behavior keeps Lv100 EXP at zero. XP bar width is capped at 100% for such saves.

Persisted monster rooms receive balance revision 2 once, retaining the fraction of HP remaining against the previous default (or administrator override). Dead HP, death/respawn timers, positions, target IDs, sessions, and player data are retained. Subsequent polls do not heal or respawn monsters due to this migration. Deployment must update client and server together. A future balance revision requires an explicit migration from its immediately previous maximum-HP table; do not reuse this release's legacy snapshot for later releases.

Validation checks the ordered 100-level table, nine ordered checkpoints, positive stats/EXP and probability range 0–1. Tests compare every XLSX row against an extracted audit fixture, every CSV checkpoint and named percentage against the original CSV, interpolation/endpoints, exact probability boundaries, independent material identities, cap behavior, administrator precedence, preserved player assets, and one-time persisted-room migration. Existing server authority, replay, party and inventory checks remain in place.

Final verification: `npm run build` passed. The targeted simulation/server/config suite passed 86 unique checks (74 initial passes plus corrected legacy elite-HP assertions, verified by rerunning all 13 elite checks). Seven refinement regression checks passed. One browser test checked complete model loading, EXP text, level cap and horizontal layout at Lv1/Lv50/Lv100 in a 1200×800 viewport; it passed without page errors.
